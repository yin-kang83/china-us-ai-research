# 双模型架构：通用"百晓生" + 领域"小李飞刀"（2026-11-18）

> 术语说明：这里是**双模型/双系统**（通用模型 + 领域专家），不是多模态。
> 目标：用路由 + 回退，把"广"和"准/快/省"结合起来。

## 一、总体架构

```
用户请求
  → 输入预处理（文本/图像/表格/语音）
  → 路由器（规则/分类器/embedding/LLM 判断）
      ├── 小李飞刀（领域专家模型：小、快、准、可本地）
      └── 百晓生（通用大模型：知识广、推理、工具调用）
  → 置信度检查
      ├── 高置信 → 返回
      └── 低置信/超纲 → 升级（专家→通用→人工）
  → 日志/评测/监控
```

## 二、两个角色

| 角色 | 职责 | 选型 | 部署 |
|---|---|---|---|
| **百晓生** | 开放域问答、跨领域推理、长尾、工具/Agent | 通用大模型（API 或开源大模型） | 云/混合 |
| **小李飞刀** | 高频、高精度、固定领域任务 | 开源小模型 + 领域 LoRA/继续预训练 | 本地/边缘/私有云 |

> 不建议两个都从零预训练；百晓生用现成底座，小李飞刀用开源小模型适配。

## 三、路由设计

| 方式 | 优点 | 缺点 |
|---|---|---|
| 规则/关键词 | 快、可控 | 覆盖有限 |
| 分类器（BERT/小模型） | 快、可训练 | 需标注 |
| Embedding 相似度 | 少标注 | 领域漂移 |
| LLM 判断 | 灵活 | 慢/贵 |
| 混合 | 规则兜底 + 分类器 + LLM | 工程复杂 |

**建议**：规则 → 小分类器 → 置信度阈值；LLM 只处理边界样本。

## 四、专家模型（小李飞刀）怎么训

1. **选开源底座**：Qwen/LLaMA 等小参数版本；
2. **数据**：领域指令/问答/文档/图像-文本对；
3. **方法**：LoRA/QLoRA 优先；数据足够再做继续预训练；
4. **评测**：领域金标准 + 与通用模型对比 + 端到端任务；
5. **迭代**：错误分析 → 补数据 → 再训；避免灾难性遗忘。

## 五、成本/延迟模型（示意）

| 变量 | 含义 |
|---|---|
| `p_s` | 专家处理比例 |
| `c_s` | 专家单次成本 |
| `c_g` | 通用单次成本 |
| `c_r` | 路由开销 |
| `L_s/L_g` | 专家/通用延迟 |

- 加权成本 ≈ `p_s·c_s + (1-p_s)·c_g + c_r`
- 加权延迟 ≈ `p_s·L_s + (1-p_s)·L_g + L_r`
- 若专家成本/延迟远低于通用，**提高 p_s** 就省钱省时；但 p_s 过高会牺牲长尾能力。

## 六、评测指标

| 指标 | 说明 |
|---|---|
| 路由准确率 | 分对领域的比例 |
| 专家精度/召回 | 领域内 |
| 端到端成功率 | 用户任务完成 |
| 升级率 | 专家→通用/人工比例 |
| 平均延迟 | P50/P95 |
| 单次成本 | 含路由 |
| 幻觉/错误率 | 人工抽检 |

## 七、失败模式

1. **路由分错**：专家答非所问；
2. **专家过度自信**：不升级，错误扩散；
3. **通用模型幻觉**：长尾场景编造；
4. **两模型口径不一致**：同一问题两种答案；
5. **维护两套**：版本/数据/评测不同步。

## 八、落地路线（建议 12 周）

| 阶段 | 周 | 任务 |
|---|---|---|
| 0 | 1–2 | 选 1 个高价值场景；建 100–300 条评测集 |
| 1 | 2–6 | 专家模型 LoRA 微调；与通用模型对比 |
| 2 | 6–9 | 路由/置信度/回退；端到端评测 |
| 3 | 9–12 | 小流量试点；监控成本/延迟/成功率 |

## 九、映射到制造业/我们的样本

| 场景 | 小李飞刀 | 百晓生 |
|---|---|---|
| 工业质检 | 缺陷分类/分割小模型（图+文） | 质检报告、根因分析、工艺建议 |
| 设备诊断 | 异响/振动分类模型 | 维修手册问答、跨设备推理 |
| 生产排产 | 排产优化小模型 | 异常解释、跨部门协调 |
| 合同/文档 | 条款抽取模型 | 合同问答、风险分析 |
| 客服 | 意图分类/FAQ 模型 | 复杂投诉、跨域问题 |

> 制造型公司（华孚/科翔/亿田/康惠/东阳光/弘信/协创）优先"质检+设备"；软件公司（赛意/东华/宝信）可做"平台+行业专家模型"。

## 十、结论

> **双模型架构可行且实用：百晓生负责"广"，小李飞刀负责"准/快/省"，路由+回退负责"稳"。**
> 关键不是模型多大，而是：**场景选对、数据够、路由准、评测严、成本算得清。**
